# PQ-CBAS-DSH — Research Artifact

Artifact accompanying *"What Post-Quantum Authentication Costs in a VANET:
Measuring ML-DSA-65 Across Device Classes in a Certificate-Based
Batched-Verification Framework"*.

Every number in Tables 5–16 and Figures 3–6 of the manuscript is regenerated by
the scripts in this bundle.

---

## Contents

```
src/        measurement code (Python)
esp32/      microcontroller-class OBU benchmark (Arduino IDE)
sumo/       StudyArea network, demand, and SUMO configuration
scripts/    run wrappers
results/    raw JSON output
docs/       platform guides and revision notes
```

---
The manuscript source is not included in this repository; see the published
article for the paper itself.

## Requirements

| | |
|---|---|
| Python | 3.11+ |
| liboqs | 0.15.0, ML-DSA-44/65/87, reference C implementation |
| Python packages | `liboqs-python`, `numpy`, `cryptography` |
| SUMO | 1.26 (headless traces) / 1.27 (Figure 3 visualization) |
| ESP32 (optional) | Arduino IDE 2.x + ESP32 core 3.3.x |

`cryptography` is required: without it the ECDSA-P256 baseline is silently
skipped and finding E1 cannot be reproduced.

## Quick start

```bash
bash scripts/run_bench.sh          # builds liboqs + venv, runs operation benchmarks
source venv/bin/activate

# Tables 5, 7, 16, 17 + ECDSA baseline (finding E1)
OQS_INSTALL_PATH=~/oqs python3 src/bench_pqcbas.py | tee results/bench.log

# Tables 9, 10 — end-to-end, 20 seeds, both transmission modes
bash scripts/run_seeds.sh 20 90

# Table 12 — SUMO mobility trace
OQS_INSTALL_PATH=~/oqs python3 src/sumo_pqcbas_bridge.py \
  --window 90 --seeds 20 \
  --cfg sumo/studyarea_test.sumocfg --net sumo/StudyAreNetwork.net.xml \
  --fcd studyarea_fcd.xml
OQS_INSTALL_PATH=~/oqs python3 src/sumo_pqcbas_bridge.py \
  --window 90 --seeds 20 --no-sumo --digest --fcd studyarea_fcd.xml

# Table 11 — transport budget and channel load (analytic, no dependencies)
python3 src/transport_budget.py --latex
```

## Confidence intervals

`src/ci_stats.py` computes across-seed CI₉₅ using a **Student-*t*** multiplier at
df = n−1, not the normal quantile. Both `e2e_workflow.py` and
`sumo_pqcbas_bridge.py` import it.

This matters: an earlier revision of this work used z = 1.96 with n = 5 and
n = 3, which understates the interval by 1.42× and 2.20× respectively. Running

```bash
python3 src/ci_stats.py
```

prints the correction factors and the rescaled values.

## ESP32 benchmark

The microcontroller-class measurement (Table 6) uses the PQClean reference
implementation of ML-DSA-65 rather than liboqs, because liboqs does not support
ESP-IDF. PQClean `clean` is the same portable C code liboqs vendors for generic
targets, so the two are comparable.

```bash
cd esp32/PQCBAS_ESP32_Bench
bash setup_arduino.sh        # fetches PQClean Dilithium3 + fips202 into src/
# then: Arduino IDE -> DOIT ESP32 DEVKIT V1 -> Upload -> Serial Monitor @115200
```

Full instructions and troubleshooting: `docs/ARDUINO_GUIDE.md`.
Scope and limitations of this platform: `docs/ESP32_NOTE.md`.

## Results directory

`results/` contains the raw JSON from the runs reported in the manuscript.
File names encode platform and configuration, e.g.
`e2e_results_W90_full_mac_m2.json`.

The 20-seed results reported in Tables 9, 10 and 12 are included as
`e2e_results_W90_{full,digest}.json` and `sumo_pqcbas_W90_{full,digest}.json`;
the `*_mac_m2.json` files are the earlier five-seed runs, retained for comparison.

**Note for re-runs:** absolute timings are platform-dependent and will differ from the Apple M2
values in the manuscript. The portable claims are the *ratios* (E1, E2) and the
*qualitative* conclusion that the collection window dominates end-to-end latency
(E3, E4).

## Known limitations

These are stated in the manuscript and repeated here so the artifact is not
over-read:

- Verification remains **per-signer**; the aggregate layer provides
  protocol-level properties, not cryptographic savings.
- The compact extension PQ-CBAS-DSH-C is **not implemented**. Its classical-ROM
  proof holds only for batch sizes m ≤ 9, and within that range its core object
  is larger than the linear aggregate.
- End-to-end measurements **exclude** wireless transport, contention and
  queueing. `src/transport_budget.py` adds the transmission term analytically;
  a full PHY/MAC simulation is future work.
- The liboqs reference implementation is standards-conformant but has **not**
  been audited for side-channel resistance on these platforms.

## Reproducibility notes

- Set the CPU governor to `performance` and verify thermal headroom before
  timing on Linux/Raspberry Pi (`docs/RPI_GUIDE.md`).
- Do **not** build liboqs with `-DOQS_OPT_TARGET=native` when reproducing the
  manuscript numbers; the reported values use the generic profile so that all
  platforms run the same reference C code.
- Benchmarks are single-threaded; core count affects build time only.
